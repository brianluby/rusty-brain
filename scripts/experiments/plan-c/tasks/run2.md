Since kanban #100, the local embedder (`crates/rb-embed/src/local.rs`, cargo feature `local`) loads `Qdrant/all-MiniLM-L6-v2-onnx` at a pinned revision (`ALL_MINILM_L6_V2`) with SHA-256-checked files, using hf-hub's cache layout: `<cache_root>/models--Qdrant--all-MiniLM-L6-v2-onnx/snapshots/<revision>/<file>`, where files may be symlinks into `../../blobs/`.

Add an OFFLINE check that never downloads, creates or modifies anything:
1. In rb-embed (feature `local`), add `pub enum PinCacheStatus { Complete, Missing(Vec<&'static str>), Corrupt { file: &'static str } }` (derive Debug, Clone, PartialEq, Eq) and `pub fn cached_pin_status(cache_root: &Path, pin: &PinnedModel) -> rb_types::Result<PinCacheStatus>`, both re-exported at the rb_embed crate root. Check files in this order: model.onnx, tokenizer.json, config.json, special_tokens_map.json, tokenizer_config.json. Any present file whose SHA-256 differs from the pin makes the result `Corrupt` (the first such file in that order), even when other files are missing; otherwise `Missing` lists every absent file in that order; otherwise `Complete`. Hash the ~90 MB onnx by streaming, not by reading it into memory.
2. Expose the cache-root resolution that loading uses (`HF_HOME`, else fastembed's `FASTEMBED_CACHE_DIR` / `.fastembed_cache`) as a pub fn and use it from `fetch_pinned` too, so the two cannot drift.
3. In `rusty-brain doctor` (`crates/rusty-brain/src/doctor.rs`), when built with the `local` feature and the local backend is selected, add a check named `local-model-cache`: Ok when Complete, Warn when Missing (hint: the first daemon start downloads it), Fail when Corrupt. Without the feature, add nothing.
